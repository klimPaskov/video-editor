# Input prompt examples

These are copyable, filled-in operator prompts for realistic screen-recording
projects. They are prompts, not executable scripts and not approval records.

## Use them in order

1. Start with [`01-basic-recording.md`](01-basic-recording.md) or the complete
   [`12-project-brief-template.md`](12-project-brief-template.md).
2. Add [`04-dense-edit-policy.md`](04-dense-edit-policy.md) for word-level
   cleanup and exact removals.
3. Add [`02-prompt-writing-focus.md`](02-prompt-writing-focus.md) and
   [`05-screen-recording-zoom.md`](05-screen-recording-zoom.md) only when the
   visible action and target are real and time-bounded.
4. Use [`07-captions-and-brand.md`](07-captions-and-brand.md) for visual
   treatment.
5. Use [`08-repair-rejected-candidate.md`](08-repair-rejected-candidate.md)
   when a rendered revision has bad cuts or zooms.
6. Use [`09-final-qa-and-watchthrough.md`](09-final-qa-and-watchthrough.md),
   then [`10-delivery-and-cleanup.md`](10-delivery-and-cleanup.md), only after
   the current review gates.

## Make a prompt concrete

Name the project and revision. Quote the words. Give approximate source times.
Describe what the viewer sees at the start and end of a speed-up or zoom. Say
what must remain normal speed. State the output profile and what must remain
untouched. Ask for evidence paths, hashes, warnings, and a review packet.

Keep source paths and private media on the local machine. Do not paste tokens,
credentials, signed URLs, or private asset contents into a prompt.
